# QA-отчёт: Архиватор
- **Репозиторий:** https://github.com/ujsss1/archiver
- **Коммит:** 243fda2 (main)
- **Дата:** 19.11.2026
- **Окружение:** Windows, .NET 10.0 (локально), Linux/Docker (CI)
- **QA-инженер:** [Твое Имя]

## 1. Что проверено
- Сборка CLI (`dotnet build`), вывод справки, коды возврата.
- Сборка и запуск HTTP-сервиса (`archiver-service.cs`).
- Проверка API: `/v1/health`, `/v1/info`, `/v1/compress`, `/v1/decompress`.
- Round-trip (сжатие -> распаковка) для текста, пустого файла, 1 байта, случайных данных, нулей.
- Lossless-проверка (сравнение SHA-256).
- Обработка ошибок (битый архив -> 400, неверный токен -> 401).
- Ручная проверка UI в браузере.
- Ручная проверка кода ядра на наличие собственного алгоритма.
- Сверка документации и кода.

## 2. Автоматизация (CI)
В репозиторий добавлен CI-пайплайн (`.github/workflows/`), который на каждый PR запускает `scripts/service-check.sh`. Скрипт поднимает сервис в Docker и проверяет health, info, 4 файла round-trip, лимит размера архива, обработку битого архива и авторизацию.
*Локальный скрипт `qa/test_api.ps1` выведен из эксплуатации, так как CI-скрипт покрывает базовые сценарии и работает в изолированном окружении.*

## 4. Дефекты
- **BUG-DOC-01 (Major):** Устаревшая документация. Описывает `zlib/lzma` вместо собственного C# алгоритма.
- *(Закрыт)* ~~BUG-API-02: PublishAot=false~~. Ожидаемое поведение, так как AOT ломает JSON-сериализацию. Сборка на Linux проверяется в CI.
- *(Закрыт как ошибочный)* ~~BUG-API-01: Неверные имена эндпоинтов~~. Проверка показала, что пути `/v1/compress` и `/v1/decompress` полностью соответствуют актуальной спецификации.

## 5. Вывод
Ядро архиватора и API работают стабильно, сжатие происходит без потерь, UI функционирует. Единственное критичное замечание — устаревшая документация, которая может сбить с толку экспертов.
