- **Дата:** 18.11.2026
- **Окружение:** Windows, .NET 10.0, Kestrel (localhost:5000), CLI
- **QA-инженер:** [Твое Имя]

## 1. Что проверено
- Сборка CLI (`dotnet build`), вывод справки, коды возврата.
- Сборка и запуск HTTP-сервиса (`archiver-service.cs`).
- Проверка API: `/v1/health`, `/v1/info`, UI-интерфейс (корневой путь `/`).
- Round-trip (сжатие -> распаковка) для текста, пустого файла, 1 байта, случайных данных, нулей.
- Lossless-проверка (сравнение SHA-256).
- Обработка ошибок (битый архив).
- Ручная проверка UI в браузере.
- Ручная проверка кода ядра на наличие собственного алгоритма.
- Сверка документации и кода.

## 3. Дефекты
- **BUG-DOC-01 (Major):** В проверенном коммите не задокументированы модели сжатия и фильтры ядра на C#.
- **BUG-API-02 (Minor):** В коде установлен `PublishAot=false`. Необходимо проверить сборку на сервере.
- *(Закрыт как ошибочный)* ~~BUG-API-01: Неверные имена эндпоинтов~~. Проверка показала, что пути `/v1/compress` и `/v1/decompress` полностью соответствуют актуальной спецификации. 404 при запросе к `/v1/compset` является корректным поведением.

## 4. Вывод
Ядро архиватора и API работают стабильно, сжатие происходит без потерь, UI функционирует. Единственное критичное замечание — устаревшая документация, которая может сбить с толку экспертов.
