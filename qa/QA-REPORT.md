- **Репозиторий:** https://github.com/ujsss1/archiver
- **Коммит:** 243fda2 (main)
- **Дата:** 18.11.2026
- **Окружение:** Windows, .NET 10.0, Kestrel (localhost:5000), CLI
- **QA-инженер:** [Твое Имя]

## 1. Что проверено
- Сборка CLI (`dotnet build`), вывод справки, коды возврата.
- Сборка и запуск HTTP-сервиса (`archiver-service.cs`).
- Проверка API: `/v1/health`, `/v1/info`, UI-интерфейс (корневой путь `/`).
- Round-trip (сжатие → распаковка) для текста, пустого файла, 1 байта, случайных данных (256 КБ), нулей (1 МБ).
- Lossless-проверка (сравнение SHA-256).
- Обработка ошибок (битый архив, неверные пути).
- Ручная проверка UI в браузере (сжатие/распаковка файлов).
- Ручная проверка кода ядра (`Codec.cs`) на наличие собственного алгоритма.
- Сверка документации и кода.

## 3. Дефекты
- **BUG-API-01 (Blocker):** Неверные имена эндпоинтов. Арена не сможет обратиться к сервису.
- **BUG-DOC-01 (Major):** Устаревшая документация. Описывает `zlib/lzma` вместо собственного C# алгоритма, что грозит штрафом.
- **BUG-API-02 (Minor):** В коде установлен `PublishAot=false` (из-за падения health при AOT). Необходимо проверить, как сервис будет собираться на сервере арены.

## 4. Вывод
Ядро архиватора и API работают стабильно, сжатие происходит без потерь, UI функционирует. **Однако проект НЕ ГОТОВ к раунду**, так как арена не сможет найти методы для сжатия из-за неверных URL-путей.
