# Описание алгоритма

## Версия 0

### Идея
Сжать данные несколькими готовыми методами и оставить самый маленький результат.
Так архиватор никогда не проигрывает худшему из методов, а для каждого файла сам выбирает подходящий.

```
данные ──┬── без сжатия
         ├── zlib
         ├── bz2          → выбираем самый маленький результат
         └── lzma
```

### Формат сжатого файла

```
[1 байт: номер метода][сжатые данные]
```

При распаковке читаем первый байт, узнаём метод и распаковываем остальное.

### Методы

| Номер | Метод | Когда выигрывает |
|---|---|---|
| 0 | без сжатия | уже сжатые данные (jpg, zip): гарантирует, что файл вырастет не больше чем на 1 байт |
| 1 | zlib (уровень 9) | маленькие файлы |
| 2 | bz2 (уровень 9) | текст и исходный код |
| 3 | lzma (preset 9 + EXTREME) | бинарные файлы, большой текст |

Номера методов записываются в сжатые файлы, поэтому их нельзя менять. Новые методы получают следующие номера (4, 5, …).

### Первые замеры

| Тип файла | Коэффициент | Лучший метод |
|---|---|---|
| текст (лицензия, 35 КБ) | 3.70 | lzma |
| исходный код Python (140 КБ) | 4.78 | bz2 |
| программа .exe (106 КБ) | 2.06 | lzma |
| библиотека .pyd (190 КБ) | 3.07 | lzma |
| картинка .jpg (1.6 МБ) | 1.03 | bz2 |
| **итого** | **1.21** | |

Распаковка во всех случаях вернула файл байт в байт.

### Выводы и что дальше
- Итог сильно тянут вниз крупные уже сжатые файлы (jpg): они почти не уменьшаются. Это главная точка роста.
- Идеи для следующих версий:
  - пересжатие JPEG без потерь (как в packJPG / Lepton);
  - разбор таблиц (CSV) по столбцам и хранение разностей чисел;
  - более сильные модели для текста (BWT, контекстное моделирование);
  - библиотеки zstd и brotli как дополнительные методы.
