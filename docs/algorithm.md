# Описание алгоритма

## Основное ядро на C#

Ядро в `core-cs/Archiver.Core/` выполняет сжатие без потерь. Для каждого файла оно выбирает модель по пробному сжатию. Предсказание битов, арифметический кодер и обратимые преобразования реализованы на C# без готовых библиотек сжатия.

### Как сжимаются данные

Модель читает файл по битам и оценивает вероятность следующего бита. Модель `CM 1-6` объединяет несколько прогнозов: один учитывает только уже прочитанные биты текущего байта, остальные используют также 1, 2, 3, 4 или 6 предыдущих байтов. После каждого бита модель корректирует веса прогнозов. Вторая модель, `CM match`, дополнительно ищет, где раньше встречалась та же последовательность из шести байтов, и использует её продолжение для прогноза.

Арифметический кодер делит числовой интервал в соответствии с прогнозом модели и оставляет часть, соответствующую фактическому биту. Чем точнее прогноз, тем меньше битов в среднем нужно для записи данных. При распаковке модель проходит те же шаги по уже восстановленным битам, поэтому таблицы вероятностей в архив не записываются.

### Как выбирается метод для файла

Ядро определяет тип по содержимому файла. Для текста и JSON оно пробует обе модели. Для двоичных файлов дополнительно пробует фильтр x86: например, вызовы одной функции из разных мест EXE могут иметь разные относительные смещения. Фильтр преобразует их с учётом позиции команды, чтобы модели было легче увидеть повтор.

Для CSV ядро сравнивает сжатие исходных строк и сжатие после группировки полей по столбцам. Так в таблице измерений рядом оказываются коды станций с другими кодами, а показания — с показаниями. Перед применением фильтра ядро выполняет обратное преобразование и побайтово сверяет результат с исходником. Такая проверка есть у обоих фильтров.

Для каждого кандидата ядро сжимает пробу и вычисляет коэффициент `размер до сжатия / размер после сжатия`. Чем он больше, тем лучше. Для данных до 255 КиБ пробой служит весь массив, для более крупных — по 85 КиБ из начала, середины и конца. Обычный порог для продолжения сжатия — 1,005.

Для JPEG, PNG и других форматов с известной сигнатурой сжатых данных ядро пробует `CM match`. Для частичной пробы порог выше — 1,04. Если в пробу вошёл весь файл, ядро уже знает размер сжатого потока и сравнивает его с исходником, учитывая один байт на число блоков. Так для тестового PNG в 232 байта удалось выбрать архив в 234 байта вместо 237 байт при хранении без сжатия. Оба размера архива включают пятибайтовый заголовок.

### Время и параллельная обработка

По скорости пробы ядро оценивает время распаковки всего файла. При автоматическом выборе оно сначала рассматривает один блок, затем при необходимости — до восьми независимых блоков с учётом числа процессоров и размера данных. Блоки обрабатываются параллельно, каждый со своей моделью. Целевой бюджет прогноза — половина лимита арены `10 с + 2 с × размер в МБ`, где 1 МБ равен 1 000 000 байт.

Если прогноз выходит за бюджет при всех доступных вариантах, ядро сохраняет исходные байты. Оно также выбирает хранение без сжатия, если готовая сжатая нагрузка занимает столько же места, сколько исходник, или больше. Поскольку выбор числа блоков зависит от измеренного времени, на разных машинах размер архива может различаться.

### Формат и восстановление

Первые пять байт архива содержат байт с сигнатурой и номером метода, затем четыре байта CRC32 исходного файла. Старшие четыре бита первого байта равны `0xA`. Младшие задают способ восстановления:

| Номер | Метод |
|---:|---|
| 0 | Исходные байты без сжатия |
| 1 | CM match |
| 2 | CM 1-6 |
| 3 | Фильтр x86 и CM match |
| 4 | Столбцы CSV и CM 1-6 |
| 5 | Столбцы CSV и CM match |

Для метода 0 после заголовка сразу идут исходные байты. Для методов 1–5 декодер читает число блоков и их границы, восстанавливает данные и отменяет фильтр, если он применялся. В конце он вычисляет CRC32 восстановленного файла. При несовпадении контрольной суммы ядро возвращает ошибку.

### Проверка через API в песочнице арены

Результаты одного прогона на ноутбуке команды, 18 ноября 2026 года. Время взято из журнала локального сервера.

| Входной файл | Исходник, байт | Архив, байт | Метод | Сжатие | Распаковка |
|---|---:|---:|---|---:|---:|
| `measurements.csv` | 50 003 976 | 12 209 140 | Столбцы CSV и CM 1-6, один блок | 29,30 с | 33,11 с |
| `img104.jpg` | 680 031 | 586 289 | CM match | 0,77 с | 0,57 с |
| `@AppHelpToast.png` | 232 | 234 | CM match | 0,11 с | 0,11 с |
| `input.bin` | 4 096 | 4 101 | Без сжатия | 0,13 с | 0,06 с |

Таблица сжалась примерно в 4,10 раза. Обе операции уложились в лимит около 110 с каждая. Для случайных байтов архив вырос ровно на размер заголовка. Во всех четырёх случаях сервер вернул исходную длину файла. В отдельном локальном прогоне проверено и побайтовое совпадение.
