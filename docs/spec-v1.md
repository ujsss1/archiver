# Проект «Собственный архиватор»: спецификация API

Версия спецификации: v1. Формальные схемы — в [openapi.yaml](openapi.yaml).

> Копия с сайта арены: https://arena.projectset.ru/docs?p=archiver (скопировано 2026-11-03). Актуальная версия — всегда на сайте.

## О проекте

### Цель

Разработать алгоритм сжатия данных без потерь, который даёт лучший коэффициент сжатия среди команд на наборе файлов разных типов.

### Описание

Команда создаёт архиватор: на вход произвольный файл, на выход сжатый файл; обратная операция должна вернуть исходный файл **побайтово идентичным**. Тестовый набор содержит данные разных типов (текст, таблицы, двоичные файлы, изображения и т. п.) размером до примерно 100 МБ; состав набора раунда заранее не раскрывается, для тренировки арена даёт открытый набор.

Полезное направление: определять тип входных данных и применять к каждому типу свой метод (или ансамбль методов). Основу сжатия команда пишет сама; готовые библиотеки сжатия допустимы только как часть собственного подхода. Решение, которое лишь вызывает готовую библиотеку (zip, zstd, LZMA и т. п.), штрафуется.

Пример недопустимого приёма: сервер сохраняет исходный файл и возвращает пользователю только ключ-идентификатор, выдавая его за «сжатый файл».

### Ожидаемый результат

1. Реализация алгоритма сжатия и распаковки (любой язык).
2. Интерфейс для пользователя: загрузить файл и получить сжатый, загрузить сжатый и получить исходный (рекомендуется веб-приложение).
3. API по этой спецификации: методы сжатия и распаковки, которые вызывает арена.
4. Краткое описание алгоритма: какие методы применены, к каким типам данных, почему.
5. Репозиторий с кодом и инструкцией по запуску.

### Критерии приёмки

| Критерий | Требование |
|---|---|
| Сжатие без потерь | Распакованный файл совпадает с исходным побайтово (проверка хешем SHA-256); несовпадение означает, что файл не сжат (коэффициент 1) |
| Самодостаточность архива | Сжатый файл содержит всё необходимое для распаковки; распаковка работает на «чистом» экземпляре сервиса без доступа к исходным данным |
| Время | Сжатие и распаковка каждого файла укладываются в лимит (раздел 4) |
| Работоспособность | API отвечает по спецификации; интерфейс позволяет выполнить оба действия |
| Собственный алгоритм | Сжатие не сводится к вызову одной готовой библиотеки |
| Главный критерий рейтинга | Суммарный коэффициент сжатия на наборе: исходный размер / сжатый размер |

### Что проверяет арена

Арена автоматически проверяет работоспособность API, побайтовое совпадение (SHA-256), время и считает суммарный коэффициент, по которому строится рейтинг. Интерфейс, описание алгоритма, собственный характер решения и самодостаточность архива оценивают преподаватели по репозиторию и на защите.

## Как проходит соревнование

### Общие условия турнира

- Команда — до 4 человек. Каждая команда выбирает один из четырёх проектов и соревнуется с другими командами по объективному критерию; эталонного решения нет, есть только лучшее на текущий раунд.
- Решения сравниваются в нескольких раундах (контрольные точки в течение семестра), финальный прогон проходит в январе. Правила могут уточняться между раундами (закрытие лазеек, усложнение задачи), но команды узнают о них до начала очередного раунда.
- Решение состоит из трёх обязательных частей: собственный алгоритм, пользовательский интерфейс для демонстрации (рекомендуется веб-приложение) и API по этой спецификации, через который арена автоматически запускает соревнование. Язык и фреймворки любые, ИИ-ассистенты и любые доступные ресурсы разрешены.
- Работоспособность важнее амбиций: решение, которое не запустилось в раунде, получает 0. Простой, но стабильно работающий алгоритм лучше сложного, который падает.
- На каждую операцию установлен разумный лимит времени; превышение означает, что операция не засчитана.
- Академическая честность: обход проверяющей системы вместо решения задачи (подмена результата, хранение исходных данных на сервере, обращение к чужому решению) ведёт к дисквалификации из раунда и снижению оценки.
- Баллы турнира учитываются при итоговой защите проекта.

### Путь команды

1. **Кабинет команды.** Войдите по ключу, который выдали организаторы, выберите проект и укажите адрес вашего сервиса (при необходимости токен). Арена вызывает ваш сервис сама, поэтому адрес должен быть доступен из интернета.
2. **Проверка API.** Кнопка «Проверить API» запускает короткий сценарий и показывает по каждому шагу, что ожидалось и что получено. Успешная проверка нужна для допуска в раунд.
3. **Тренировка.** Прогон на открытом наборе файлов (раздел 8): видно коэффициент по каждому файлу, время и сравнение с простым эталоном. Количество тренировочных прогонов в час ограничено.
4. **Раунд.** Организаторы запускают прогон на закрытом наборе файлов; по нему считается суммарный коэффициент и строится рейтинг раунда. Результаты видны вам в кабинете, общая таблица появляется после публикации организаторами.

Отладить сервис на своём компьютере можно в песочнице в браузере (страница «Песочница»): она вызывает сервис на localhost напрямую, без выкладки в сеть.

## 1. Что делает ваш сервис

Ваш сервис по запросу сжимает файл и по запросу распаковывает архив обратно **побайтово идентично**. Арена пропускает через сервис набор файлов, замеряет размеры и время и вычисляет суммарный коэффициент сжатия.

## 2. Протокол

| Метод | Тело запроса | Тело ответа |
|---|---|---|
| `POST /v1/compress` | байты файла (`application/octet-stream`) | байты архива |
| `POST /v1/decompress` | байты архива | байты исходного файла |

- Тела передаются **сырыми байтами**, без обёрток и JSON. Загрузка потоковая (`Transfer-Encoding: chunked` допустим); читайте тело потоком, файлы до 100 МБ.
- Дополнительные заголовки запроса: `X-Arena-File` (идентификатор файла в наборе), `X-Arena-Size` (размер тела в байтах).
- Ответ `200`; при ошибке `4xx/5xx` и тело по общему контракту. Архив не должен превышать `2 × исходный размер + 1024` байт (иначе файл считается неуспешным).

## 3. Как идёт прогон

1. Арена берёт набор файлов (закрытый набор в раунде; открытый малый набор для `check` и `practice`).
2. **Фаза сжатия:** файлы по одному отправляются на `/v1/compress`; арена сохраняет полученный архив, размер и время.
3. **Пауза**, затем **фаза распаковки:** архивы отправляются на `/v1/decompress` в **другом порядке**, по новым соединениям. Сервис не получает ни имени файла, ни соответствия «архив → оригинал».
4. Арена сравнивает SHA-256 распакованного файла с оригиналом.

Служебные файлы набора:
- **несжимаемый файл**: случайные байты, генерируются при каждом прогоне. Архив заметно меньше оригинала означает, что данные хранятся на сервере, и прогон помечается для разбора;
- файлы с «солью»: уникальные байты в начале файла, поэтому заранее подготовленные ответы не помогут.

## 4. Время

На операцию действует лимит `timeoutMs = baseMs + perMbMs × размер_МБ` (в v1: 10 000 мс + 2 000 мс на каждый МБ). Превышение = операция не засчитана. Лимиты и значения приходят в журнале прогона и в расписании раунда.

## 5. Оценка

| Исход | Файл |
|---|---|
| Сжатие и распаковка прошли, SHA-256 совпал | `ratio = исходный / архив` |
| Ошибка, таймаут, несовпадение хеша, архив слишком большой | файл считается **несжатым**: в суммах участвует исходным размером в числителе и знаменателе (коэффициент 1) |

Итог: **суммарный коэффициент** `Σ исходных / Σ архивов`. Вторичный показатель — суммарное время (при равенстве коэффициента с точностью до 0,001 выше команда с меньшим временем).

## 6. Требования к решению

- Архив самодостаточен: распаковка работает на «чистом» экземпляре сервиса без доступа к исходным данным. Арена проверить это полностью не может, проверка кода остаётся за преподавателем.
- Готовые библиотеки сжатия допустимы только как часть собственного подхода; решение, сводящееся к вызову одной готовой библиотеки, штрафуется. Арена фиксирует коэффициент и время, оценку «оригинальности» ставят эксперты по описанию алгоритма.
- Недопустимо хранить исходники на сервере и возвращать ключ. Нарушение = дисквалификация из раунда.

## 7. Проверка соответствия (`mode=check`)

1. `GET /v1/health`.
2. Три малых файла (текст, двоичный, нулевые байты): сжатие и распаковка, хеш совпадает.
3. Пустой файл (0 байт): сжатие и распаковка.
4. Некорректный архив на `/v1/decompress`: ответ `4xx` без падения сервиса.

## 8. Тренировка (`mode=practice`)

Открытый набор: 20 файлов (≈ 3 МБ) — русские и английские тексты, таблицы CSV, JSON, двоичные записи, почти нулевые файлы, картинки PNG, маленькие файлы, файл из одного байта, пустой файл — плюс один случайный (несжимаемый) файл 64 КБ. Таблица результатов: файл, размер, архив, коэффициент, время сжатия и распаковки, итог. Сравнение с эталоном (простейший RLE+Хаффман, deflate со стратегией RLE) на том же наборе. Тренировочный прогон выполняет арена, поэтому сервис должен быть доступен по публичному адресу (хостинг или туннель, например cloudflared или ngrok). Без выкладки в сеть можно отлаживаться в песочнице в браузере (вкладка «Архиватор»): она проверяет API вашего сервиса на localhost и прогоняет через него любые ваши файлы, показывая коэффициент, время и совпадение хеша. Для больших файлов лучше использовать прогон арены.

В раунде набор закрытый: имена файлов не показываются, к каждому файлу добавляются 16 уникальных байт «соли» в начале, несжимаемый файл имеет размер 256 КБ.

## Общие правила API

Эти правила действуют во всех проектах арены и приведены здесь полностью, отдельного общего документа нет. Арена ходит к решениям команд по одинаковым правилам, поэтому один слой арены (проверка API, журнал, лимиты, повтор) обслуживает все проекты.

### Кто кого вызывает

Решение команды — HTTP-сервер по адресу, который вы указали в кабинете. Арена — клиент: ваш сервис только отвечает на запросы и сам арену не вызывает. Адрес должен быть доступен из интернета (хостинг или туннель); адреса `localhost` арена вызвать не может, для них есть песочница в браузере.

### Служебные методы

| Метод | Назначение |
|---|---|
| `GET /v1/health` | Ответ `200 {"status":"ok"}`. Арена вызывает его в проверке API и ждёт не дольше 3 с, отвечайте быстро |
| `GET /v1/info` | Необязательно: `{"name","version","project","specVersion"}` |

Остальные методы описаны в протоколе проекта.

### Заголовки запросов арены

| Заголовок | Значение |
|---|---|
| `Authorization: Bearer <token>` | Токен команды, если он задан в кабинете. Проверяйте его, если хотите закрыть сервер от посторонних |
| `X-Arena-Run` | Идентификатор прогона или партии |
| `X-Arena-Spec` | Версия спецификации (`v1`, `v2`…) |
| `X-Arena-Mode` | `check` (проверка API), `practice` (тренировка), `round` (зачётный раунд) |
| `X-Arena-Seq` | `1` на фазе сжатия, `2` на фазе распаковки (операции не зависят друг от друга, идемпотентность не требуется) |

Арена не передаёт ни в заголовках, ни в теле ничего, кроме заданий: ни скрытых параметров и наборов, ни данных других команд.

### Время и повторы

- На каждую операцию действует лимит `timeoutMs = baseMs + perMbMs × размер_МБ` (раздел 4). Превышение = файл считается неуспешным (раздел 5).
- **Без повторов.** Арена не повторяет запрос после таймаута или ошибки; поздний ответ отбрасывается.
- Запросы одного прогона идут последовательно, из одного потока. Разные прогоны одной команды могут идти параллельно, но не более `maxConcurrentPerTeam` (настройка организатора, по умолчанию 1).

### Формат ошибок

Если решение не может обработать запрос, оно отвечает кодом `4xx/5xx` и телом:

```json
{ "error": { "code": "bad_state", "message": "что случилось" } }
```

Арена показывает тело команде. Для архиватора любая ошибка, таймаут или неверный результат означают, что файл считается несжатым: коэффициент 1 (раздел 5).

### Журнал и воспроизводимость

Арена хранит таблицу прогона по файлам: размер, размер архива, время сжатия и распаковки, причина отказа. Содержимое файлов и архивов не сохраняется; имена файлов закрытого набора командам не показываются.

### Проверка API (`check`)

Кнопка «Проверить API» в кабинете запускает короткий сценарий в режиме `check`. Он проверяет формат ответов, время и обработку ошибочных данных, но не оценивает качество. Успешная проверка — условие допуска в раунд. В отчёте по каждому шагу видно: что ожидалось, что получено, сколько заняло. Сценарий описан в разделе 7.

### Безопасность

- Арена не обращается к loopback и внутренним сетям (`localhost`, `10.*`, `192.168.*`, `172.16–31.*`, адреса служебных диапазонов).
- Арена не следует переадресациям: ответ `3xx` считается ошибкой.
- Тело ответа на `compress` не должно превышать `2 × исходный размер + 1024` байт, ответ на `decompress` — исходный размер + 1024 байт; больший ответ арена обрывает, файл считается неуспешным.
- Токен команды хранится только у арены и у команды. По возможности публикуйте сервис по HTTPS.

### Версии

Версия спецификации передаётся в `X-Arena-Spec` и фиксируется в раунде. Новый раунд может выпустить `v2`; описание изменений команды получают до его начала. Решение может объявить поддерживаемые версии в `GET /v1/info`.
