## Цель недели
1. Сервис по спецификации доступен из интернета и **проходит «Проверить API»** на арене.
2. Первый **тренировочный прогон** на арене (пока на версии 0 как временном ядре).
3. Прототип **собственного** метода сжатия (готовая библиотека в одиночку штрафуется).

## Что важно из спецификации
- Оценка: `Σ исходных / Σ архивов` — крупные файлы решают всё.
- Ошибка, таймаут или неверный хеш — файл считается несжатым (коэффициент 1). Сервис не запустился — 0 за раунд.
- Лимит времени на операцию: `10 с + 2 с × размер в МБ`.
- Архив не больше `2 × размер + 1024` байт.
- Готовые библиотеки — только как часть своего подхода.

## Подробнее

**@Pacifist381 — алгоритм**
- Арифметическое кодирование: сжимает данные почти до предела, если хорошо предсказывать следующий байт. Предсказывает модель (сначала по частотам байтов, потом по предыдущим байтам — контексту).
- Замер скорости: прототип на Python на файле 1 МБ. Если дольше ~2 с, ядро переносим на компилируемый язык.
- Обновить таблицу замеров в `algorithm.md` после прототипа.

**@NORDIC-01 — API и интерфейс**
- Протокол строго по разделу 2 спецификации: тела запросов и ответов — сырые байты, без JSON.
- `GET /v1/health` отвечает `{"status":"ok"}` быстрее 3 с.
- Любая ошибка распаковки — ответ `4xx` с телом `{"error":{"code":"...","message":"..."}}`, сервис при этом не падает.
- Ядро подключать через функции `compress(data) -> bytes` и `decompress(data) -> bytes` из `core/compressor.py`.

**@ujsss1 — DevOps**
- Арена вызывает сервис сама, адреса `localhost` и внутренних сетей ей недоступны, переадресации (`3xx`) считаются ошибкой.
- Ключ команды для кабинета выдают организаторы.

**@koldoval — QA**
- Тренировочный набор арены: русские и английские тексты, CSV, JSON, двоичные записи, почти нулевые файлы, PNG, маленькие файлы, 1 байт, пустой файл, случайный файл 64 КБ.
- Проверять: совпадение SHA-256, время по формуле лимита, размер архива ≤ `2 × размер + 1024`.
